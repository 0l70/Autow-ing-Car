# 📜 프로젝트 기여 가이드 (CONTRIBUTING)

이 문서는 우리 팀의 **Git 브랜치 전략, 커밋 메시지 규칙, Merge Request(MR) 프로세스**를 정의합니다.
원활한 협업과 지라(Jira) 연동을 위해 모든 팀원은 아래 규칙을 준수해 주세요.

---

## 1. ⚡ 개발 환경 자동화 (필수 Setup)

프로젝트를 클론(Clone) 받은 직후, **가장 먼저 아래 스크립트를 실행해 주세요.**
복잡한 규칙을 외울 필요 없이, 커밋 메시지와 MR 링크 생성을 자동화해 줍니다.

### 🚀 실행 방법

터미널에서 프로젝트 루트 경로(최상위)에 위치한 뒤, 아래 명령어를 **딱 한 번만** 입력하세요.

```bash
sh scripts/init_setting.sh
```

### 🛠️ 무엇이 설정되나요?

1. **Git Hook 설치:** `feat: 로그인`이라고만 적어도 👉 `[S14P...-56] [FE] ✨ Feat: 로그인` 형태로 자동 변환됩니다.
2. **MR Alias 등록:** `git mr` 명령어 입력 시 👉 제목과 옵션이 완성된 **MR 생성 링크**가 출력됩니다.

---

## 2. 🌿 브랜치 이름 규칙 (Branch Naming)

브랜치 이름은 **작업 종류, 설명, 지라 이슈, 파트**를 명확히 알 수 있도록 작성합니다.

### ✅ 명명 구조

> **`타입/설명-지라키[-컴포넌트]`**

* **타입 (Type):** 작업의 성격 (폴더로 구분)
* **설명 (Description):** 작업 내용 (영어 소문자, 띄어쓰기는 하이픈 `-`)
* **지라키 (Jira Key):** `S14P11A402-번호` (필수)
* **컴포넌트 (Component):** `fe`, `be`, `pm`, `em` (선택 사항)

### 📝 작성 예시

* **Front-end:** `feat/login-ui-S14P11A402-56-fe`
* **Back-end:** `feat/signup-api-S14P11A402-59-be`
* **Embedded:** `feat/camera-node-connect-S14P11A402-61-em`
* **Common/PM:** `docs/readme-commit-rule-S14P11A402-56-pm`

---

## 3. 💬 커밋 메시지 규칙 (Commit Message)

자동화 스크립트(`init_setting.sh`)를 실행했다면, **헤더 포맷을 자동으로 맞춰줍니다.**
하지만 기본 구조는 반드시 숙지해 주세요.

### ✅ 커밋 구조

```text
[이슈키] [컴포넌트] 이모지 태그: 제목

- 본문: 무엇을, 왜 변경했는지 상세 설명 (선택 사항)
- 꼬리말: 이슈 닫기 등 (선택 사항)
```

### 🎨 이모지 및 태그 리스트 (Gitmoji)

| 이모지 | 태그 (Type) | 설명 |
| --- | --- | --- |
| ✨ | **Feat** | 새로운 기능 추가 |
| 🐛 | **Fix** | 버그 수정 |
| 💄 | **Design** | CSS, UI/UX 디자인 변경 (로직 변경 없음) |
| 📝 | **Docs** | 문서 수정 (README, 주석, 위키 등) |
| ♻️ | **Refactor** | 코드 리팩토링 (기능 변경 없음, 구조 개선) |
| 🎨 | **Style** | 코드 포맷팅, 공백 등 (동작 영향 없음) |
| ✅ | **Test** | 테스트 코드 추가 및 리팩토링 |
| 🔨 | **Chore** | 빌드 설정, 패키지 매니저, 라이브러리 설치 |

## 4. 🔀 Merge Request (MR) 규칙

코드를 `develop` 브랜치에 병합할 때 지켜야 할 프로세스입니다.
터미널에서 `git mr`을 입력하면 **2번(Title)**과 **5번(Option)**이 자동 완성된 링크가 생성됩니다.

### 1️⃣ 기본 설정 (필수 🚨)

* **Change branches:** Target을 `master` ➡️ **`develop`**으로 반드시 변경!
* **Assignee:** 본인 지정 (`Assign to me`)
* **Reviewer:** 팀원 최소 1명 지정 (검토 필수)

### 2️⃣ Title (제목)

* 포맷: `[지라키] 이모지 태그: 핵심 내용`
* 예시: `[S14P11A402-56] ✨ Feat: 로그인 API 생성`

### 3️⃣ Mark as draft (진행 상태)

* ✅ **Draft (WIP):** 작업 중일 때 체크 (머지 버튼 잠김)
* ⬜ **Ready:** 개발 완료 시 해제 (리뷰 및 머지 요청)

### 4️⃣ Merge Options

* ✅ **Delete source branch:** **필수 체크** (머지 후 브랜치 자동 삭제)
* ⬜ **Squash commits:** **체크 해제** (커밋 히스토리 보존)

### 5️⃣ MR 내용 템플릿

MR 생성 시 Description에 아래 내용을 복사하여 작성합니다.

```markdown
## 📝 작업 요약
- (예시) 카카오톡 API 연동

## 😈 주의 해야 할 점
- (예시) KEY.env 파일 최신화 할 것

## ✅ 체크리스트
- [ ] Merge 되는 브랜치가 `develop`이 맞나요?
- [ ] 리뷰어를 지정했나요?
```

---

## 💡 주의사항 (Tips)

1. **지라 연동 필수:** 커밋 메시지와 MR 제목에는 반드시 `[S14P...-번호]` 키가 포함되어야 지라(Jira)와 연동됩니다. (자동화 스크립트 사용 권장)
2. **제목 작성:** 제목은 "~함", "~구현", "~수정" 처럼 명사형이나 과거형으로 간결하게 작성합니다.
3. **VS Code 팁:** Gitmoji 확장 프로그램을 설치하면 커밋 창에서 이모지를 쉽게 입력할 수 있습니다.
